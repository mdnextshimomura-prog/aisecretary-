## 3. 「何の依頼？」のボタン（段3）

LINE の書き出し 968 件の集計（11/24）から決めた8つ：

［査定］［資料を送る］［書類の作成・チェック］［日程・内見］［物件調査・謄本］［振込・お金］［メール・電話］［その他］

- 出る所：下村さんの1対1だけ。グループには出さない
- 出る時：段1の入口で受付票を開いたとき。段1は「査定らしいもの」だけを拾っているので、まずは**段1の入口のまま**、カードの上の段にこの8つを置く（AI の見立てに当たるボタンを先頭にし、色を変える）
  - 入口を「依頼全般」に広げる（査定以外の言葉でも受付票を開く）のは段2の範囲外。費用（AI の呼び出し）と送信枠が増えるので、査定で動きを見てから
- 押したら：
  - ［査定］→ 案件を選ぶ（段1の gs・gl・gm）→ 案件が決まったら段4へ
  - それ以外の7つ → **受付と記録だけ**。LINEタスク に `種別の依頼`＝押した種類で書く（タスクがあるとき。無いときは受付票に印だけ）。返事は「〈種類〉として控えました。中身は手作業でお願いします」。中身の自動化はそれぞれ別の設計
  - ［メール・電話］も記録だけ。メールを作る段を足すときも、**下書きまで**（送るのは下村さんの OK のあと）
- data：`v1|gk|<ticketId>|<ver>|<種類の符号>`（符号は `satei`・`doc`・`check`・`sched`・`survey`・`money`・`mail`・`other`）。決めるのは受付票ごとに最初の1回（段1の `gsatei:dec:` を使う）

## 4. 資料から拾う・足りなければ聞く（段4・5）

- 段1の読み取り（所在・物件名・種別の見込み）を広げて、**専有面積／土地面積・築年月・間取り・階・総戸数・構造**も読む（同じ1回の読み取りで。AI の呼び出しは増やさない）
- 足りない項目の決まり（査定書の表紙・概要に要るもの）：
  - マンション：所在・物件名・号室・専有面積・築年月
  - 戸建：所在（地番か住居表示）・土地面積・建物面積・築年月
  - 土地：所在（地番か住居表示）・土地面積
- 足りなければ、個人LINEに**1回に1つ**聞く（「専有面積が分かりません。分かれば送ってください（例：65.3）」＋［分からない］）。答えは次の1対1の文字を受ける（差し戻し理由の取り込みと同じ型の印 `gsatei:ask:<userId>`、30分）
- ［分からない］なら空のまま進む。査定係が「確認事項」に「〇〇は担当が確かめる」と書く
- お客様の名前は読まない・残さない（段1の守りのまま）

## 5. 公開データを集める（段6）

**どこで**：Mac の査定係（line-secretary）。aisecretary（Vercel）は時間の上限が短く、地図・PDF を保存できないため。

- 査定係に「地域の調べ」の段を足す（v1 で外した `area/` の段を、条件つきで戻す）
- **検索に使ってよいのは住所・地番・町丁目・最寄り駅だけ。** お客様の名前・ファイル名・資料の本文は検索語に入れない
  - 仕組みで守る：調べの段に渡すのは、所在（住所か地番）と種別だけの小さな入力ファイル。資料のフォルダ（`input/`）はこの段から読めないようにする（sandbox）
- 取るもの：用途地域・建ぺい率・容積率・防火・ハザード（洪水・土砂・津波）・小中学校区・地価（公示・路線価）・前面道路の幅員（取れる市だけ）・位置図
  - 手段：国の不動産情報ライブラリ（API。REINS 由来のデータは使わない）を先に。足りない所は Web 検索・Web の地図（市の都市計画図・道路台帳）
  - 幅員は市ごとに作りが違う。取れなければ「幅員は担当が確かめる」と確認事項に書く
- **ゼンリン**：ログインは人（Claude は ID・パスワードを入れない、ログインボタンも押さない）。切れていれば個人LINEに1回だけ「ゼンリンにログインしてください（住宅地図を取ります）」。ログインされなければ地図なしで進む。「登記取得」ボタンは押さない（課金）
- **登記簿**：自動では取らない（課金）。要るときは個人LINEで「〇〇の登記簿を取ってよいですか」と聞くだけ。取るのは人
- 結果は案件フォルダの `01_物件資料/地域調査/` に保存（PDF・画像・`調査結果.md`）。査定書の「エリア・校区」の欄に使う

## 6. REINS の事例の相談と、山口さんへの依頼（段7・8）

### 6.1 相談（個人LINE）
- 段4〜6が済んだら、査定係（Mac）が事例の取り方の案を作り、aisecretary 経由で個人LINEへ：
  ```
  〈案件名〉の REINS の事例を、次の条件で山口さんに頼んでいいですか？
  ・成約：同じマンション＋半径500m・築±5年・過去3年・10件ほど
  ・売出：同じ条件で5件ほど
  期日：明日 17時
  ```
  ［いいよ］［直す］
- 条件の決め方は、査定スキル（realestate-satei）の「事例の採用」の考え方に合わせる（種別ごとの既定）
- ［直す］→「直すところを1通で送ってください（喋ったままで大丈夫です）」。答えを読んで案を作り直し、もう一度［いいよ］［直す］（2回まで。3回目は手で頼む案内）

### 6.2 山口さんへの依頼（グループ）
- ［いいよ］のあと、**依頼が来たグループ**に、山口さんにメンションしたカードを push（ボタンなし）：
  ```
  @山口さん
  査定の事例をお願いします（受付 G7）
  物件：〈町名・物件名。号室・番地は入れない〉
  ・成約：…
  ・売出：…
  期日：11/26 17時
  取れたら、このトークに PDF を貼ってください
  ```
- 文面に入れないもの：お客様の名前・REINS の物件番号・号室・番地（グループの全員が見るため）
- **グループへの送信は、この依頼カードとリマインドの2つだけ**（段1の「グループに何も返さない」の例外。ほかの段は今までどおり返さない）
- 山口さんの LINE userId は env `GROUP_SATEI_CASE_STAFF_ID`（1人。名簿から選ぶのは後）
- リマインド：期日を過ぎても事例の PDF が控えに無ければ、グループに1回だけ「@山口さん 受付 G7 の事例はいかがでしょうか」。下村さんの個人LINEにも1行。2回目は出さない
- 送信枠：1件につきグループへ最大2通

## 7. 事例の PDF を受け取って保存する（段9）

- グループに PDF が貼られたら（段1の控えに乗る）、受付票が「事例待ち」で開いているかを見る
  - そのグループで事例待ちの受付票が1件だけ、または引用リプライで受付票のカードを指している → その受付票の事例とみなす
  - 2件以上で引用が無い → 下村さんに「どの受付の事例ですか」＋受付票のボタン
- 保存は Mac（line-secretary。Drive に書く口を持っている）：
  - aisecretary に新しい口 `POST /api/satei/media`（合言葉 `x-satei-token` = HMAC(JOB_API_TOKEN, "satei-media")）。Mac が受付票の番号を渡すと、その受付票の事例 PDF を LINE から取り出して返す（1回1件・20MB まで）
  - Mac が案件フォルダの `02_査定・事例/REINS成約/`（売出は `REINS売出/`）に保存。ファイル名は `事例_G7_1.pdf` の形（元の名前は使わない）
  - LINE の保管期間は保証が無いので、貼られてから1時間以内に取りにいく（Mac の見回り2分おきに相乗り）
- 保存できたら、個人LINEに「事例を保存しました（成約 n件）。下書きを作ります」→ 今の査定係の流れ（段10・11）へ

## 10. 受付票の状態（段1から足すもの）

`asking`（段1）→ `kind`（種類を選んだ）→ `gathering`（資料・公開データ）→ `asking-info`（足りない項目を聞いている）→ `proposing`（事例の相談）→ `waiting-cases`（山口さんに頼んだ）→ `saving`（保存中）→ `started`（下書きへ）／`manual`／`dismissed`／`expired`

- 期限：段1は7日。段2は `waiting-cases` から**さらに7日**（事例が遅れても消えない）
- 状態はこれまでどおり KV の受付票に置く。Mac とは portal の依頼箱で受け渡す（11節）

## 11. aisecretary と Mac の受け渡し

- 段4〜5は aisecretary（読み取り・聞く）
- 段6〜7の案づくり、段9の保存、段10は Mac
- つなぎ方：［査定で進める］のあと、aisecretary が portal の受付に**「準備」の依頼**（`prep`）を出す。Mac の査定係が見回りで受け取り、段6をして案を作り、aisecretary の `POST /api/satei/propose` で個人LINEに出す。［いいよ］の答えは portal 経由で Mac に戻り、Mac が aisecretary の `POST /api/satei/case-request` でグループに依頼を出す
- どの口も今と同じ合言葉の型（HMAC(JOB_API_TOKEN, "<口の名前>")）。新しい環境変数は `GROUP_SATEI_CASE_STAFF_ID` だけ
- portal（reins-report）の依頼箱に `prep` の種類を足す必要がある（portal 側の変更）

## 12. スイッチ

- `GROUP_SATEI_STAGE2`（aisecretary。既定 off。off なら段1のまま1バイトも変えない）
- `SATEI_AREA_RESEARCH`（line-secretary。既定 off。off なら Web を使わない今の作り）
- `SATEI_PREP`（portal。既定 off）
- 入れる順：portal → Mac → aisecretary。止めるのは逆順

## 13. プライバシー

- 検索・外部 API に出すのは住所・地番・町丁目・駅だけ。仕組み（入力ファイルを分ける・sandbox）で守る
- グループの依頼カードに、お客様の名前・号室・番地・REINS の番号を入れない
- KV・ログには ID・時刻・種類・符号だけ。ログは `[group-satei] G7 kind satei`・`propose sent`・`case-request posted`・`cases saved 3` の形
