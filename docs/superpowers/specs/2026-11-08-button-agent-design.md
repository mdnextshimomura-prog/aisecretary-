# LINE を全部ボタンで回し、押したらエージェントが動く（aisecretary）設計書（2026-11-08・下書き）

壁打ち: 下村さん × Claude Code（2026-11-08）。前段: 業務指示グループのカード型ボタン（fe81aa0・58e4719、本番稼働、実機で「めっちゃ便利」）。経緯の正は vault `20_research/2026-08-08_AI秘書_集約と完了機能_進行ログ.md`。

## 1. 下村さんの要望（原文の要約）
1. 案件をカードで次々に表示して、チェックできるようにしたい
2. タスク登録もボタンでできるようにしたい
3. 社長から曖昧な指示が来たときの登録のしかたを決めたい
4. ボタンを押したら AI エージェントが動き出す（Grok / Claude Code / Codex のどれでも）。例：登記簿を取る（ログインして取得）。レインズは人が取って格納→「入れた」で査定書を作り始める
5. 「Codex と打ち合わせして最大限形に」

## 2. 決めていること（前提）
- 作業役は Claude Code と Codex。Grok には顧客情報を渡さない（2026-11-07 決定。個人の xAI 契約に流れるため）
- レインズは自動で触らない（人が取って入れる。realestate-satei も REINS に触れない前提）
- 有料の取得（登記簿など）は、取得の前に必ず下村さんの［取得を承認］ボタン。結果不明なら再取得せず照合
- ログインの ID・パスワードは Claude が入力・保存しない。下村さんが Mac のキーチェーンに自分で登録し、取得は決まった手順のスクリプト（AI ではない）が読む
- 社外への送信・署名・確定は人
- 曖昧な指示で依頼者（社長）には聞き返さない。秘書が読み取りを出し、下村さん（または担当）がボタンで埋める ← **下村さん確認待ち（仮決め）**

## 4. B1 ボタンの入口（aisecretary だけで完結）
### 4-1. メニュー
- 「@秘書」だけ（またはメニューの言葉）で［今日・期限切れ］［自分の未完了］［候補］［案件］のカードを出す。以後は文字を打たずにボタンでたどれる。
### 4-2. 候補を1件ずつカードに（17時と、迷った依頼を共通化）
- 候補1件＝カード1枚（カルーセルは運用上10枚まで。11件目からは［次の10件］）。ボタン［登録する］［保留］［いらない］。
- 17時のまとめは残す。迷った依頼（@秘書 あて・確信度0.5〜0.7）は、その場で同じカードを出す。
- data には表示番号ではなく候補の ID。候補の保存を1件ずつの原子的な更新にし、登録の予約で二重登録を防ぐ（今の一覧の全置換はやめる）。
- 対象グループ：今の候補は営業部（LINE_GROUP_ID）だけ。業務指示グループにも広げる（要設定）。
### 4-3. 未完了タスクの再掲
- ［今日・期限切れ］［自分の未完了］で、タスク1件＝今のタスクカード1枚。押した後は今のボタン（済・待ち・延期・不要・担当）。
### 4-4. 案件をカードで（B1 の後半）
- 進行中の CRM_案件 を1件1枚。中身：案件名・フェーズ・近い期日・残りタスク数。ボタン［タスクを見る］［タスクを足す］。読むだけ（CRM の欄には書かない）。
### 4-5. 曖昧な指示（保留）
- Codex の指摘：「必ず登録」は雑談の誤登録と確認の手間を増やし、今の文字の聞き返しとの二重管理になる。
- B1 では、曖昧な依頼は 4-2 の候補カード（［登録する］［保留］［いらない］）に乗せるだけにする。秘書の読み取り＋足りない項目の候補ボタンは、B1 を1週間使ってから決める。
- 社長には聞き返さない（下村さんか担当が押す）を仮決め。

## 5. B2 材料がそろったら査定書の下書き
### 5-1. 流れ
1. 案件カードの［査定書を作る］（または「入れた」）。案件とフォルダが**人の確定済み**でなければ、まず案件を選ぶカードに戻す（TASK_RECORD の紐付けは「候補あり」で、確定ではないため）
2. Mac が案件フォルダを見て材料の一覧を返す（Vercel は Mac のフォルダを読めないので、材料確認も Mac の仕事）。
   - 着手できない条件（成約事例・物件種別・面積など、スキルが必須とするもの）が欠けたら作らない
   - 欠けても下書きできる資料（公図など）は不足一覧を付けて作れる
3. portal の依頼箱にある既存の種類 `satei` に、Mac の**査定専用の実行役（新設）**をつなぐ（今の worker.js は帯替えの検品用で、作成はしない。帯替えの処理を止めないよう別にする）
4. 実行役が realestate-satei で製本 PDF・編集元 Excel・出典・不足一覧を作る → 別の AI（Codex）が realestate-satei-check で検品＋原資料との照合・数式の再計算・PDF の見た目確認
5. 結果を portal に登録 → 配達役が LINE に［下書きを見る］［OK］［差し戻し］カード。OK で完成。社外に出すのは人
### 5-2. 状態
材料確認待ち → 実行待ち → 作成中 → 検品中 → 人の確認待ち → 承認済み（差し戻し）。作成の成功と、LINE に届いたかは別の状態にする。
### 5-3. 守ること
- 二重実行：「案件＋業務＋入力の版」で実行中の依頼を1つに。古い実行役の結果は受け付けない。資料を差し替えたら版が変わる
- Mac が寝ていても落とさない：LINE→portal に即保存→Mac が起きたら取る。その間は「受付済み・Mac 待ち」と表示
- 工程ごとの時間切れ・生存確認・取消・Mac 再起動後の照合。最初は同時1件、自動の作り直しは最大1回
- 10/23 の Codex 試作（版の失効・lease・成果物のハッシュ）の部品を使う
- 成果物の配達：今の配達の道の4MB上限で、添付付き製本 PDF が通るか要確認
### 5-4. 案件フォルダ
- CRM の案件 ID → Drive のフォルダ ID → Mac の場所、で引く（名前で探さない。案件フォルダは移動するため固定パスにしない）
- 決め方は `マイドライブ/CLAUDE.md` と ②売買配下の既存ルールに従う（計画の前に読む）

## 6. B3 登記簿（人が取る形から）
- ［登記簿を取る］→ 取るもの（地番／家屋番号・種類・件数・見込み額。全部事項 330 円、地図・図面 360 円）をカードに → **下村さんだけ**が［取得を承認］。承認は「対象・種類・件数・上限額・期限・版」に結び付け、変わったら承認し直し
- 承認されたら担当（人）が取って案件フォルダに入れ、［格納した］→ Mac が照合して「届きました」
- 自動取得はしない（今は）。理由：約款に過度な検索の利用制限（第12条の2）があり、無人操作の可否は運営への確認事項。6回のパスワード誤りで一時停止、Mac は動作保証外、追加認証の有無は未確認
- 将来自動化するなら：規約の確認後、取得スクリプト・ブラウザ・キーチェーンを AI の実行環境から切り離す（AI に Bash 権限があるとキーチェーンだけでは隔離にならない）

## 7. 安全の決まり
- 権限を分ける：案件を見る／作成を始める／成果物を承認する／有料の取得を承認する
- 送り主の制限（業務指示グループなど）が postback より先（今のまま）
- postback の data には短い ID だけ。本文・パス・承認内容はサーバー側
- 返事は受けたらすぐ reply（1回限り・1分以内）。長い処理の結果は push
- 送信枠：月 5,000 通（2026-11-08 時点で今月 420 通使用）。push は受け取る人数分数える。完了の知らせは原則1回、途中経過はボタンで見に行く
- 資料の中の命令（「これを無視して…」など）には従わない
- 顧客情報は Notion・portal・Mac・Claude/Codex・会社の Google ドライブの外に出さない。ログに本文・ID を出さない
- 費用：作成・検品・作り直しをまとめて、依頼ごと・1日ごとの枠を先に取る
- 受け入れの試験：連打、Mac の翌朝復帰、途中停止、資料の差し替え、古い版の承認、送信枠の超過、有料取得の結果不明
