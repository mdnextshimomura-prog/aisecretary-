# 「案件はどれですか」のカード（POST /api/satei/ask・/api/satei/ask/answers）設計

2026-11-22。下村さんの承認：このセッションで「作ってよい」（agent-hub のセッションからの頼みを受け、本人に直接確かめた）。
約束の案：agent-hub `docs/contracts/2026-11-19-satei-ask.md`。下の「約束の案から変えた点」は 11/22 に相手のセッションへ伝えた。

## 何のためか
LINE WORKS に届いた査定の依頼は、どの案件の話かを機械では決められない。受け口（hub）は案件が決まらないと止まる。
そこで、下村さんとの普通の LINE の1対1に候補のカードを出し、1タップで選んでもらう。Mac がその答えを取りに来て、受け口に出し直す。
秘書は査定を始めない（始めるのは、答えを受け取った Mac → hub → 今の /api/satei/request の道）。

## 口1：カードを頼む `POST /api/satei/ask`
- 鍵：ヘッダ `x-satei-token` = HMAC-SHA256(`JOB_API_TOKEN`, `"satei-ask"`) の小文字 hex（知らせ・依頼の口とは別の文）。JOB_API_TOKEN が無い・32字未満なら誰も通さない。
- 本文（これ以外の欄は 400）：`askId`（`/^[0-9A-Za-z]{10,64}$/`）、`receipt`（`/^H[1-9][0-9]{0,8}$/`）、`reason`（`MISSING_CASE`／`TOO_OLD`）、
  `occurredAt`（タイムゾーンつき ISO 8601）、`excerpt`（80字まで）、**`propertyHint`（任意・60字まで。足した欄）**。
- 順番：鍵 → 形 → `TASK_SATEI` が off・宛先（`TASK_SATEI_USER_IDS` の先頭）が無い → `{result:"rejected", code:"TASK_SATEI_OFF"}` → KV が無い → `unknown`。
- 同じ askId：出せたもの（`sent`）は出し直さず `{result:"ok", created:false}`。控えはあるが送れたか分からないものは、同じ再送キーで送り直す
  （X-Line-Retry-Key = uuidv5(askId)。LINE が再送キーを覚えているのは24時間）。最初に送ろうとしてから23時間を過ぎたものは送り直さず
  `{result:"rejected", code:"ASK_UNCERTAIN"}`（二重に届くのを避ける。Mac は下村さんに確かめてもらう）。
- 候補：`propertyHint` を物件名と同じ規則でそろえ、進行中の CRM_案件 の名前（「｜」で分けた各部分）と照らす。完全一致→部分一致の順で最大5件。
  1件だけ当たっても確定しない（ボタンを出すだけ）。ヒントが無い・当たらない・CRM が読めない → 候補なし（［一覧から選ぶ］［査定にしない］だけ）。
  **抜粋そのものでは照らさない**（照合は完全一致が基本なので、文のままではほぼ当たらない）。
- カード：1対1へ push（月の送信枠を1通）。受付番号・発言の日時（日本時間）・抜粋・（TOO_OLD なら「24時間より前の発言です。まだ必要なら選んでください」）・候補のボタン・［一覧から選ぶ］・［査定にしない］。グループには出さない。
- LINE が 200・409 → 控えを `sent` にして `{ok, created:true}`。それ以外・時間切れ → `{result:"unknown"}`（Mac がもう一度呼べば同じキーで送り直す）。

## ボタン（postback）
- data：候補・一覧の［この案件］`v1|qa|<askId>|<案件ID>`、［一覧から選ぶ］`v1|ql|<askId>|<オフセット>`、［査定にしない］`v1|qn|<askId>`。
- 押せるのは `TASK_SATEI_USER_IDS` の人だけ。`TASK_SATEI` が off なら「いまは止めています」。
- ［一覧から選ぶ］：進行中の案件を名前順に10件ずつのカルーセル（各［この案件］）＋［次の10件］。読むだけ。
- ［この案件］［査定にしない］：二度押し・再送は `pb:<webhookEventId>` の予約で止める。答えは **最初の1回だけ有効**（SET NX）。2回目以降は「選択済みです（〇〇）」。
  案件は進行中の一覧にあるものだけ受ける。`label` は CRM_物件 の物件名（案件の `物件` の1件目）。「様」「邸」「さん」「氏」を（切る前の全文で）含めば空、そうでなければ60字で切る。読めなければ空のまま受ける。
- 控え（askId の印）が7日で消えたあとに押されたら「この確認は期限が切れています」。

## 口2：答えを取りに行く `POST /api/satei/ask/answers`
- 鍵は口1と同じ。本文 `{ "after": "<位置>" }`（最初は空文字。位置は答えの通し番号の数字）。
- 答えは KV に1件ずつ（`sateiask:ans:<askId>`・7日）と、通し番号の目次（`sateiask:answers`・番号は `sateiask:seq`）。
  答えを置くのと目次に番号を振って載せるのは、Redis の中の1回の処理（Lua）。番号は置いた順なので、Mac が位置を進めたあとに小さい番号が現れることはない。
  押したときに通信が切れて目次に載らなかった答えは、押し直したとき（「選択済み」と返す前）に載せ直す。
  位置より後の答えを番号の順に最大50件と、次の位置を返す。7日を過ぎて消えた答えは目次から外す。
  位置を進めるまでは何度でも同じ答えが返る。**7日を過ぎた答えは消える**（Mac が7日より長く取りに来なければ取りこぼす）。
- 答えの形は約束の案のとおり（`deal` は dealId・label つき、`none` は無し）。お客様の名前・文面は入れない。
- TASK_SATEI が off でも、すでにある答えは返す（止めているあいだの取りこぼしを防ぐ）。

## 守ること
- ログは符号だけ（`[satei-ask] H12 asked 3`・`skip:…`・`qa saved` の形）。抜粋・案件名・userId は出さない。
- 新しい環境変数は無い（`TASK_SATEI`・`TASK_SATEI_USER_IDS`・`JOB_API_TOKEN`・`CRM_DEALS_DB_ID`・KV をそのまま使う）。止めるときは `TASK_SATEI` を外す（ほかの査定の機能も止まる）か、Mac の側で呼ばない。
- `src/middleware.ts` の matcher には入れない（入れると Mac が 401 になる）。
- 「査定にしない」を hub に記録する操作は hub の側で作る。

## 置き場所
- `src/lib/satei-ask.ts`：判断・カード・2つの口・ボタン（deps を受け取るだけ）
- `src/lib/satei-ask-wire.ts`：本物（KV・CRM・LINE）
- `src/app/api/satei/ask/route.ts`・`src/app/api/satei/ask/answers/route.ts`
- postback の振り分けは `task-buttons-wire.ts`（satei のボタンの隣）
- テスト `tests/satei-ask.test.ts`

## Codex のレビュー（11/22）で直したこと
1. 答えの順番を時刻から Lua の通し番号へ（遅れて置かれた答えを位置が飛び越えて取りこぼすため）
2. 答えの保存と目次への追加を1回の処理に。目次の載せ直し（保存後に通信が切れると、Mac に永久に見えない答えが残るため）
3. 23時間を過ぎた結果不明のカードは送り直さない（LINE の再送キーは24時間で忘れられ、二重に届きうるため）
4. 敬称の判定は切る前の全文で（61字目以降の「様」を切り落として名前の頭が残るため）
