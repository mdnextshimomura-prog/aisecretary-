# LINEグループから帯替えを依頼し、グループに完成リンクを返す 設計

日付：2026-10-09　決定者：下村さん（会話で承認）
関係するリポジトリ：
- `apps/aisecretary`（公式アカウント「MD NEXT秘書」の Webhook。Vercel）…この設計書の置き場所
- `apps/reins-report`（portal。Railway）
- `apps/line-secretary`（Mac の LINE秘書。launchd）と、その中の `delivery/`（閲覧ページ。Vercel `mdnext-doc-delivery`）

## 目的
今は帯替えの依頼を LINE WORKS の秘書室からしか出せず、完成リンクも秘書室にしか届かない。社長などがグループ（【MDNEXT】業務指示＝`tools/line-send/宛先.json` の「営業部」）に貼った PDF を、下村さんがグループの中で一言頼むだけで帯替えし、グループに完成リンクが届くようにする。

## 決めたこと
1. **依頼できるのは下村さんだけ**。発言者の LINE userId を許可リスト（環境変数 `JOB_ALLOWED_USER_IDS`）で判定する。下村さん以外が依頼の形で送ったら「帯替えの依頼は下村さんからお願いします」とだけ返す
2. **依頼の形**：MD NEXT秘書へのメンション＋「帯替え（帯かえ・帯変え・オビ替え）＋物件名」。読み方は line-secretary の `src/jobs/parse.js` と同じ（物件名・`担当:`）
3. **使う PDF**：依頼の時点からさかのぼって **30分以内にそのグループに出た PDF（誰が貼ったものでもよい）を最大20件**、出た順に使う。画像・PDF 以外のファイルは使わない。受付の返事に使ったファイル名を書く
4. **運ぶのは MD NEXT秘書（aisecretary）**：依頼を受けたその場で LINE から PDF を取り出し、portal の既存 API（`POST /api/jobs` → `POST /api/jobs/{no}/inputs`）に送る。Mac が止まっていても受付と下準備は進む
5. **受付の返事はグループに**（reply）：「#J12 受付しました（物件：○○／PDF：a.pdf ほか2件）。完成したらここにリンクを出します」
6. **完成リンクもグループに**（push）。Mac の LINE秘書が今の納品（Drive 保存・リンク発行）をしたあと、受付の返事先がグループならグループへ送る。秘書室にも従来どおり控えを送る
7. **グループに出したリンクは、グループの一員なら開ける**（名簿の登録は要らない）。LINE ログイン＋グループ在籍の確認は今どおり行う。秘書室あてのリンクは今どおり名簿も見る
8. **大きい PDF も開けるようにする**：今の閲覧ページは 4.4MB（Vercel の応答の上限）までしか渡せない。帯替えの完成品は1ページ約0.7MB（実物：3ページで2.1MB）なので、7ページを超えると開けない。分けて渡して閲覧側でつなぐ（下の「閲覧ページ」）

メッセージの枠：MD NEXT秘書は月5,000通（2026-10-09 時点で使用107通）。グループへの push は人数分（約17通）数えるが十分足りる。受付の返事は reply なので数えない。

## 流れ
1. グループに PDF が出る → aisecretary が「グループごとの直近の PDF」に控える（message.id・ファイル名・大きさ・出た時刻。30分で消える。最大20件）
2. 下村さんが依頼 → aisecretary が
   1. 許可リストを確認
   2. 直近の PDF を選ぶ（無ければ「直近30分に PDF がありません。PDF を貼ってからもう一度送ってください」）
   3. LINE から PDF を取り出す（`api-data.line.me/v2/bot/message/{id}/content`）。`%PDF-` で始まらないものは外す
   4. `POST /api/jobs`（`workflow:'obi'`、`lineMessageId` は依頼のメッセージの id＝二重受付を防ぐ、`property`、`requestText`、`requestedBy:'下村'`、**新しく `replyTarget`**）
   5. `POST /api/jobs/{no}/inputs`（multipart、`x-batch-id` は使う PDF の id から決める）
   6. グループに受付の返事（reply）
3. portal は今と同じ（自動の下準備 → 自動完成。Discord にも経過）
4. Mac の LINE秘書が完成を見つけて納品 → `replyTarget` がグループなら、グループに「#J12 帯替えが完成しました（物件名）＋リンク＋要確認のページ数」を push。秘書室にも控え

## 影響する所
### aisecretary（`apps/aisecretary`）
- グループの直近の PDF の控え：今は「送った人×グループ」で30分・5件（`src/lib/email/session.ts`）。帯替え用に **グループ単位・30分・20件** の控えを別に持つ（既存のメール・タスク用の控えは変えない）
- 依頼の判定：Webhook（`src/app/api/webhook/route.ts`）で、メンションの判定のあと・既存のタスク受付の前に帯替えの分岐を入れる。帯替えの形でなければ今までどおり
- portal への送信：新しいモジュール（例：`src/lib/obi-job.ts`）。鍵は `JOB_API_TOKEN`、宛先は `PORTAL_BASE_URL`
- 時間：PDF の取得と送信が reply の期限内に終わらないことがあるので、関数の実行時間（`maxDuration`）を延ばし、間に合わなければ受付の返事を push に切り替える
- 冪等：同じ依頼の再送は既存の `reserveEvent` と portal の `lineMessageId` で1回だけ
- 新しい環境変数（Vercel）：`PORTAL_BASE_URL`・`JOB_API_TOKEN`・`JOB_ALLOWED_USER_IDS`（下村さんの LINE userId。Notion の名簿か Webhook の記録から確かめる）。**追加は下村さんの承認後、値を画面に出さない方法で入れる**

### portal（`apps/reins-report`）
- Job に `replyTarget`（文字列。例：`line-group:<groupId>`。無ければ従来＝秘書室）を足す（prisma のマイグレーション）
- `POST /api/jobs` で受け取り、`GET /api/jobs`（Mac が完成を探す一覧）で返す。形の検査（決まった接頭辞と ID の形だけ通す）
- それ以外（下準備・自動完成・納品の記録）は変えない

### Mac の LINE秘書（`apps/line-secretary`）
- `src/jobs/deliver.js`：`replyTarget` がグループなら、リンクの発行後にグループへ push（既存の `src/lineapp.js pushText`。宛先は `宛先.json` の「営業部」に固定し、`replyTarget` のグループ ID と一致したときだけ送る＝誤送信の防止）。秘書室には控え
- グループへの送信が失敗しても、秘書室に送れていれば納品は成功として記録し、秘書室に「グループに送れませんでした」と書く
- リンクの発行：グループあてのトークンに「グループ在籍で開ける」印を入れる（下の閲覧ページ）

### 閲覧ページ（`apps/line-secretary/delivery`）
- 名簿の確認（`lib/gate.js` の④）：トークンに「グループ在籍で開ける」印があれば名簿を見ない。在籍の確認（⑤）は必ず行う。印はトークンの署名の内側に入れる（外から足せない）
- 大きい PDF：4MB 以下の部分に分けて渡し、閲覧側でつないで表示する。部分ごとに同じ確認（トークン・ログイン・在籍・失効）を通す。**つないだ全体の sha256 をトークンの値と照合**してから表示し、合わなければ表示しない。回数の制限は部分の数を見込んで決める。保存用の入口（`/api/dl`）も同じ大きさまで扱えるようにする
- 上限は portal の完成品の上限（40MB）に合わせる

## うまくいかないとき
| 場面 | 返事（グループ） |
|---|---|
| 直近30分に PDF が無い | 直近30分に PDF がありません。PDF を貼ってからもう一度送ってください |
| 前の帯替えを処理中（portal の `OBI_BUSY`） | 前の帯替え（#J11）を処理中です。終わってからもう一度送ってください |
| 受付停止中（`INTAKE_STOPPED`） | いま帯替えの受付を止めています |
| 多すぎる・大きすぎる | 上限（20件・1件40MB）を書いて断る |
| LINE から PDF を取り出せない・portal に届かない | 受付できませんでした（理由）。秘書室にも知らせる |
| 下村さん以外の依頼 | 帯替えの依頼は下村さんからお願いします |
| 完成リンクをグループに送れない | 秘書室にリンクと「グループに送れませんでした」 |

## 確かめ方
- aisecretary：依頼の判定・PDF の選び方（30分・20件・誰が貼ったものでも・PDF 以外は外す）・許可リスト・portal への送信（失敗の各場面）を単体テストで固定。LINE と portal は偽物に差し替える
- portal：`replyTarget` の受け取り・形の検査・一覧での返却を vitest で固定
- LINE秘書：グループあての納品・誤送信の防止・グループへの送信失敗を既存のテストの形で固定
- 閲覧ページ：印の有無で名簿を見る／見ない、分けて渡す・つなぐ・sha256 の照合を固定
- 実地：本番のグループで下村さんが1件依頼し、受付の返事・完成リンク・別の社員がリンクを開けることを確かめる（実在のお客様の資料は使わず、テスト用の図面で）

## 対象外
- 「2番直して」などの番号での直し（次の設計）
- 査定の依頼、PDF 以外の画像の帯替え
- グループ以外（個別トーク）からの依頼
