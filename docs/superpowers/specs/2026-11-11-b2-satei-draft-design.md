# B2 マンションの査定書の下書きをボタンで作る 設計書（2026-11-11）

親の設計書：`2026-11-08-button-agent-design.md` 第5節。この文書はその詳細で、食い違えばこちらを正とする。

## 1. 決めたこと（下村さん 2026-11-11）
- 最初の種別は**マンション**だけ。他の種別の案件では作らない
- きっかけは **LINE の案件カードの［査定書を作る］ボタン**（秘書室の「査定 物件名」は作らない）
- 組み方は **A案：帯替えと同じ道**（営業支援システム reins-report の依頼箱 → Mac の係 → 配達役 → `15_AI納品`）
- 下書きのカードは**秘書室**へ届け、［OK］［差し戻し］を押せるのは**下村さんだけ**
- 作るのはテンプレート Excel の正式な査定書（realestate-satei）。reins-report の画面の「簡易査定」は使わない

## 2. 流れ
1. 担当がレインズの成約事例などを、案件フォルダの `02_査定・事例` に入れる
2. 案件カードの［査定書を作る］を押す（試行中は下村さんの userId だけ。他の人には「いまは下村さんだけが使えます」）
3. aisecretary が CRM_案件 の「Driveフォルダ」欄と案件番号（DEAL-####）を読み、reins-report の依頼箱に `satei` の依頼を作る。押した場所には「受け付けました。結果は秘書室に届きます（Mac の順番待ち）」とだけ返す（案件名・金額は出さない）
   - 同じ案件で終わっていない `satei` 依頼があれば作らず「作成中です（J番号）」と返す
4. Mac の**査定係**（新しい常駐。帯替えの係・検品係とは別）が依頼を予約して取る
5. 案件番号で案件フォルダを探す（下の第5節）。0件・2件以上なら止めて秘書室へ知らせる
6. 材料を確かめる（第4節）。足りなければ作らず「入力待ち」にし、秘書室へ不足一覧とボタン［入れたのでもう一度］
7. Claude（`claude -p`）が realestate-satei で、製本 PDF・編集元 Excel・出典一覧・不足一覧を作る。作業場所は Mac の `line-secretary/cases/satei/J番号/`（git 管理外）。**案件フォルダには書かない**
8. Codex が realestate-satei-check で検品する（形式・数値の再計算・根拠、原資料との照合、ページ画像の目視）。判定が「差し戻し」なら指摘を渡して**1回だけ**自動で作り直し、もう一度検品。それでも差し戻しなら、その判定のまま下村さんへ回す
9. 下書き PDF を `15_AI納品/年月/査定/J番号_物件名.pdf` に保存し、秘書室へカード：判定（そのまま出せる／要修正／差し戻し）・指摘の上位3件・［下書きを見る］［OK］［差し戻し］
10. ［OK］→ 案件フォルダの `02_査定・事例` に `物件名_査定書_YYYYMMDD.pdf` として写しを1つ入れて完成。社外に出すのは人
11. ［差し戻し］→ 「理由を一言返信してください」→ 返信を理由として記録 →［作り直す］で 7 から（理由を Claude に渡す）

## 3. 状態（reins-report の Job の状態を使う）
| 段 | Job の状態 | 中身 |
|---|---|---|
| 受付 | 受付 | ボタンで作られた |
| 材料が足りない | 入力待ち | 不足一覧を秘書室へ。［入れたのでもう一度］で下準備中へ |
| 作成・検品 | 下準備中 | 査定係が予約中（lease と生存確認） |
| 下村さんの確認 | 確認待ち | 下書きのカードを秘書室へ送った |
| OK | 完成 → 納品中 → 納品済み | 案件フォルダへ写しを入れる。入れたか分からなければ納品要確認 |
| 差し戻し | 差し戻し | ［作り直す］で下準備中へ |
| 止まった | 失敗／取消 | 時間切れ2回・フォルダが特定できない など |

- 今の表は `差し戻し → 確認待ち` だけなので、**`satei` に限り** `差し戻し → 下準備中` を足す（obi の表は変えない）
- 「下書きができた」と「秘書室に届いた」は別に記録する（届いたか不明なら再送ボタン）

## 4. 材料の確認（作らない条件）
着手しない（入力待ち）：
- `02_査定・事例` に成約事例の PDF が1つもない
- 種別がマンションでない（`00_案件.md` か Notion の種別で判定。判定できなければ止める）
- 専有面積・所在が資料から読めない
不足一覧を付けて作る：売出事例がない、管理費等が不明、謄本がない など（realestate-satei の決まりどおり）

## 5. 案件フォルダの探し方
- 案件番号 `DEAL-####` で、`マイドライブ/②売買/S0NN_*/01_売買/*/` と `02_買取/*/` の直下から `DEAL-####_` で始まるフォルダを探す
- 探さない場所：`⓪自動化システム【削除禁止】`（名前を見る前に外す）、`99_旧資料`、`01_案件`（移行の一時置き場）、`★成約`
- Notion の「Driveフォルダ」欄の ID と、見つけたフォルダの ID が一致しなければ止める（名前だけで決めない）
- 箱の移動は担当が行うので、場所は毎回探し直す（固定パスにしない）

## 6. 守ること
- **二重実行**：1案件につき動いている `satei` 依頼は1つ。依頼には「入力の版」（`02_査定・事例` と `00_案件.md` のファイル名・大きさ・更新時刻から作るハッシュ）を付ける。［OK］を押したときに版が変わっていたら写しを入れず「資料が変わったので作り直してください」
- **古い結果を受け付けない**：予約（lease）が切れた係や、版の違う結果は捨てる（10/23 の Codex 試作の考え方を依頼箱側で使う）
- **Mac が寝ていても落とさない**：依頼は依頼箱に残る。Mac が起きたら取る
- **時間切れ**：作成 40 分、検品 20 分。切れたら1回だけやり直し、2回目は失敗にして秘書室へ知らせる。同時に作るのは1件
- **書き込み先**：案件フォルダへは［OK］のあとの写し1つだけ。それ以外は読むだけ。`15_AI納品` は今の配達役が書く
- **外へ出さない**：お客様の資料は Grok に渡さない。レインズは触らない。ログには J番号・件数・符号だけ（案件名・氏名・金額は出さない）
- **スイッチ**：aisecretary `TASK_SATEI=1`（既定 off。off ならボタンを出さず、今の動きは1バイトも変わらない）、試行者 `TASK_SATEI_USER_IDS`。Mac 側は査定係の launchd を入れない限り動かない

| 場所 | 中身 |

| aisecretary | 案件カードに［査定書を作る］、CRM_案件 の「Driveフォルダ」・案件番号の読み取り、依頼箱への登録、秘書室の［OK］［差し戻し］［作り直す］［入れたのでもう一度］の処理 |

## 8. 試し方と合格
1. 各リポジトリの単体テスト（スイッチ off で今と同じ、二重受付、版の違い、時間切れ、フォルダが0件・2件）
2. 過去のマンション案件の**写し**（本番の案件フォルダではない試験用フォルダ）で、端から端まで流す
3. 実際のマンション案件1件で、秘書室に下書きが届き、検品と下村さんの目視の両方で通ること → 合格
- 本番に出す前に Codex のレビューで「可」をもらい、下村さんの確認を取る
