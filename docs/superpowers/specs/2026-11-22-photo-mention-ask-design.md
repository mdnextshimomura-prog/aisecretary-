# 画像のあとの「@下村」だけの名指しを読んで、下村さんの1対1で聞く 設計

2026-11-22。下村さんの承認：agent-hub のセッションで承認された内容を、このセッションで本人に確かめて「作ってよい」。

## 困っていたこと
11/20 11:41 に社長が業務指示のグループへメモの画像（物件名・号室・購入額・転勤の予定）を送り、11:42 に「(返信) @下村亮太」とだけ送った。中身は査定の依頼だった。
aisecretary は画像を「直近のメディア」として控えるだけで、@AI秘書 あてでない名指しは読まない（task-intake の mention-none）。Mac の見張りは LINE WORKS 側で画像を読めない。結果、誰も拾わなかった。

## すること
グループで次が全部そろったら、その画像を読み、査定の依頼らしければ下村さんの1対1へ知らせる。
1. スイッチ `PHOTO_MENTION_ASK=1`（既定 off）、かつグループが `PHOTO_MENTION_GROUP_IDS`（カンマ区切り。空なら何もしない）に入っている
2. メンションの中に、LINE の mention の userId が下村さん（`TASK_SATEI_USER_IDS` の先頭＝査定の知らせの宛先と同じ人）のものがある。AI秘書へのメンションは無い（あればいつものタスク受付へ）
3. 送り主は下村さん本人ではない
4. メンションを除いた本文が空か短い一言（20字以内）
5. 同じ人が同じグループに30分以内に送った画像が控えにある（既存の `emailmedia:<group>:<user>`。引用リプライでも、引用元ではなく送り主の控えを使う）

読み方：既存のタスク判定 `parseTaskFromMessage`（画像を添えて Claude で読む。新しいプロンプトは作らない）。`isTask` かつ `requestType === "査定書"` のときだけ知らせる。それ以外は何もしない（ログに符号だけ）。

知らせ（下村さんの1対1へ push。月の送信枠を1通使う）：
- 文字：「📷 業務指示のグループで、画像つきで下村さんあての名指しがありました。〈物件名〉の査定の依頼に見えます」＋「画像は LINE のグループで確かめてください」
- 物件名が CRM_案件（進行中）と完全に一致して1件に絞れたら、2通目に［査定書を作る］のカード（既存の `v1|sa|<案件ID>`＝押すと今の査定の受付。押せるのは今どおり TASK_SATEI_USER_IDS の人だけ）。TASK_SATEI が off、または絞れなければカードを付けず「案件カードの［査定書を作る］から押してください」
- 自動で査定は始めない（案件の確定は下村さんの1タップ）

## 守ること
- グループには何も返さない（reply トークンは使わない）
- 名指しの判定は mention の userId。名前の文字では判定しない
- ログは符号だけ（`[photo-ask] asked` / `skip:<理由>` / `not-satei` / `read-failed` / `push-failed`）。画像の中身・物件名・本文・userId・groupId は出さない
- 画像は既存のとおり Claude（Anthropic API）にだけ渡す。Grok Bot・agent-hub の受け口には渡さない
- 同じ発言で二度聞かない：`photoask:<message.id>` を SET NX（1日）。予約が取れなければ聞かない
- 控えた画像は消さない（あとで @AI秘書 あての依頼が来たときに今までどおり使えるように）
- 読む・知らせるのに失敗しても、ほかの流れ（候補・手打ちの @秘書 の案内）は今までどおり

## 置き場所
- `src/lib/photo-ask.ts`：判定（条件1〜5）と文面とカード。deps を受け取る
- `src/lib/photo-ask-wire.ts`：本物（KV・画像の取得・parseTaskFromMessage・loadActiveDeals・push）
- `src/app/api/webhook/route.ts`：メンションなしの枝（⑥）で、候補の処理のあと・`finishNoBotMention` の前に呼ぶ
- テスト `tests/photo-ask.test.ts`（通信は全部差し替え）

## 出す
aisecretary だけ（portal・Mac は変えない）。本番に入れても `PHOTO_MENTION_ASK` を入れるまでは動かない。
on にするときは下村さんの承認後、`PHOTO_MENTION_GROUP_IDS` に業務指示のグループの ID を入れる。

## Codex の設計確認（11/22）を受けて変えたこと・決めたこと
- 画像の選び方：引用リプライなら引用された画像だけ（送り主の控えに無ければ別の画像で代わりにせず、読まずに「画像を読めませんでした」を送る）。
  引用が無ければ、控えた時刻（`PendingMedia.at` を足した）が発言の30分前〜1分後の画像を新しい方から3枚。時刻の無い古い控えは使う。PDF は使わない。
- 読めない（取れない・時間切れ・形が違う）ときは黙らず「画像を読めませんでした。LINE のグループで確かめてください」を送る（依頼が消えないように）。
- 確信度：0.5 未満は聞かない、0.7 未満は「査定の依頼かもしれません」（断定しない）。読んだ結果の形は実行時に確かめる。
- 二重：予約の鍵は画像の ID の組（無ければ発言の ID）。同じ画像に別の発言で名指しし直しても二度聞かない。push は X-Line-Retry-Key（uuidv5）つき。
- 時間：画像1枚8秒・AI 40秒・CRM 8秒の上限。ログは自前の読み込みで符号だけ（既存の loadRecentAttachments は ID・ファイル名を出すので使わない）。
- CRM が読めなくても知らせは送る（カードだけ省く）。カードには案件名と画像から読んだ物件名を並べる（「｜」の一部だけの一致を人が見比べられるように）。
- Ruling：「お客様の名前を外に出さない」の承認の中身は「Grok Bot・受け口（agent-hub）へ渡さない」。Anthropic（Claude）への画像は、今の @AI秘書 の画像つき受付と同じ扱いで、承認の範囲内と判断した（Codex は「Claude にも渡すな」と読んだ）。違っていたら AI で読むのをやめ、固定文の知らせだけにする。
- Ruling：webhook の中で読む（後回しの仕組みは入れない）。イベントは順番に処理されるので、同じ webhook に入った次のイベントが最大で約1分遅れうる。今の候補・@AI秘書 の受付も同じく中で AI を待っている。LINE の再送は無効の前提。
- Ruling：候補のその場の返事・手打ちの @秘書 の案内は今のまま（この処理はグループに返さないが、ほかの機能の返事は止めない）。
