# 曖昧指示をAIが業務指示に変換する設計

## 1. 目的

LINEに流れる主語のない短い指示を、人間が毎回解読し直すのではなく、AIが以下の形まで整理してNotionのタスクにする。

- 対象の物件・顧客・案件
- 具体的にやること
- やってはいけないこと
- 完了時に何が出来上がるか
- 担当候補とその理由
- 期限とその根拠
- まだ判断できないこと

目標は「AIが全て正解する」ことではない。AIが8割まで指示書を作り、人は間違った部分だけを直せる状態を目指す。

## 2. Claude CodeとClaude APIの役割

- Claude CodeやCodex：プログラムとルールを作る開発用。どちらか一方に限定する必要はない。
- Claude API：Vercel上でLINEの発言を実際に考え、返信とNotionタスクを作る本番用。

開発ツールを切り替えても、Vercelが読める場所に業務ルールが無ければ本番の判断精度は上がらない。

## 3. 本番AIに渡す情報

### 常に渡す

1. 対象のLINEメッセージと添付資料
2. 同じグループの直前の会話
3. Notionの進行中タスクのうち、物件名・顧客名・担当者が近いもの
4. Notionのメンバー名簿と担当可能業務
5. Obsidianから選別した承認済み業務ルール

### 渡さない

- Obsidianの金庫全体
- 今回の判断に関係しない個人情報
- APIキー、パスワード、カード情報
- 古いルールや作成中のメモ

## 4. Obsidianの扱い

Obsidianは業務知識の保管場所として使う。ただし、Vercel本番環境からMac内のObsidianは直接読めない。

そのため、承認済みルールだけを `knowledge/` へ書き出し、GitHubとVercelに同期する。本番AIはこの選別済みルールのみを読む。

```text
Obsidian（元の業務知識）
  ↓ 承認済みのものだけ同期
GitHub / knowledge（本番用の短い判断ルール）
  ↓ デプロイ
Vercel上のClaude API
  ↓
LINE返信 + Notionタスク
```

## 5. AIの出力形式

AIは文章だけではなく、毎回同じ項目で結果を返す。

```json
{
  "isTask": true,
  "confidence": 0.86,
  "subject": "対象物件または案件",
  "action": "具体的に行う作業",
  "doNotDo": ["公開しない"],
  "expectedOutput": "確認結果の報告",
  "assignee": "担当候補",
  "assigneeConfidence": 0.72,
  "assigneeReason": "担当業務と進行中案件から推定",
  "dueDate": "2026-09-05",
  "ambiguities": ["確定価格が不明"],
  "clarification": {
    "needed": false,
    "question": null,
    "options": []
  }
}
```

## 6. 自動判断の段階

### 信頼度0.85以上

- Notionへ「未着手」で登録
- LINEにAIの解釈を明示
- 間違っている場合だけ訂正してもらう

### 信頼度0.60以上0.85未満

- Notionへ「要確認」で仮登録
- AIの最も有力な解釈をLINEに返す
- 「対象はAですか、Bですか」のように選択肢は最大2個まで

### 信頼度0.60未満

- 原文は必ずNotionへ控える
- 担当者や金額を勝手に確定しない
- AIは不明点を1つに絞り、推定を添えて質問する

## 7. 必ず人間に残す判断

- 売買価格・買取価格の最終確定
- 契約条件の最終確定
- 送金・発注・解約・対外送信
- 法的判断、特約、重要事項説明の確定
- 従業員の評価や懲戒に関わる判断

## 8. 実装順序

1. LINEの直前文脈を短時間保存し、Claude APIに渡す
2. Notion名簿に「主担当業務」「対応可能業務」「代替担当」を追加する
3. 進行中のNotionタスクから関連候補を取得し、Claude APIに渡す
4. Obsidianの承認済みルールを `knowledge/` へ同期する
5. AIの解釈をLINE返信とNotionページ本文に残す
6. 訂正された内容を記録し、判断ルールの改善候補にする

## 9. 現在足りないデータ

Notionのメンバー名簿には、氏名・LINE userId・呼ばれ方はあるが、業務分担はない。担当者の自動推定を始める前に、少なくとも次を登録する。

- 主担当部門：売買／賃貸／管理／買取再販／事務
- 対応可能な作業：査定、契約書、物件資料、レインズ、管理会社確認など
- 代替担当：不在時に誰へ回すか
- 承認が必要な業務：自動割当してよい範囲

## 10. 成功条件

- 主語のない指示でも、対象と作業内容がLINE返信で分かる
- 一般的な「どう対応しますか？」を出さない
- 他人の会話や別件の返信をタスクに誤反映しない
- 担当未定のまま放置されるタスクが減る
- 人が確認するのは、AIが作った解釈の訂正部分だけになる

## 12. Google Driveを案件量へ使う条件

現在のDriveは、1案件に複数ファイルがあり、同じ案件を複数のフォルダ構成で管理している。したがってファイル数・フォルダ数をそのまま案件数にはしない。

Drive側は各案件フォルダの `00_案件インデックス.md` または専用の案件一覧シートへ、最低限次の項目を揃えてから集計対象にする。

- 案件ID（重複しない番号）
- 物件名
- 分類（売買／買取再販）
- 主担当
- 状態（進行中／契約予定／引渡待／完了／保留）
- Notion案件ページURL

当面の正本（簡単にいうと、最も信頼する元データ）はNotionの案件ボードとする。Driveは資料保管場所として使い、案件IDとNotion URLで結び付ける。Driveの構造が揃った後に、Drive由来の案件も負荷点へ加える。

## 13. 現在見つかった整備課題

- 2026-09-04：NotionのCRM案件・売買案件進捗・売却案件へ橋本さんの担当選択肢を追加済み
- 2026-09-04：新規タスクの受付は `@AI秘書` へのメンションを必須とする。メンションなしの通常会話や「お願いします」には反応しない
- `@AI秘書` と社員を同時にメンションした場合は、その社員を担当者として優先する。AI秘書だけをメンションした場合は業務区分と負荷から自動割当する
- `@AI秘書 お願いします` だけで直前の画像・PDFも無い場合は、曖昧なタスクを作らず、案件名と作業内容を1回で確認する
- AI秘書へ明示的に依頼されたタスクは、担当・案件要約・不足条件を返信し、回答が揃ったら担当者へ引き渡す
- Vercelの `CRM_DEALS_DB_ID` を現行のCRM案件ボードへ揃える必要がある
- Driveに「売買案件」という異なるフォルダ構成が複数あり、案件の二重計上が起き得る
- 週報シートには自社物件と担当者があるが、既存担当者を自動で変更してはいけない

本番の負荷集計は、同じ案件の二重計上を避けるため、CRM案件を優先して1つの案件ボードだけを採用する。Google Driveとの案件ID統一は次段階で行う。
